# AGENTS.md と HEARTBEAT.md は1つずつで十分な理由

OpenClawの仕様と今回の「司令塔アーキテクチャ」に照らし合わせると、ユーザー様の推察が100%正しいと言えます。その理由と、OpenClawがそれをどうやって実現しているか（仕組み）を解説します。

### 1. ワークスペースは全セッションで「共有」される

OpenClawでは、メインセッション（DM）であろうと、SlackチャンネルAのセッションであろうと、エージェントIDが同じであれば、**参照するワークスペース（デフォルトでは `~/.openclaw/workspace/`）は共通**です 。
システムプロンプトを構築する際、OpenClawは必ずこのワークスペースのルートにある `AGENTS.md` や `HEARTBEAT.md` などのファイルを読みに行きます 。そのため、ルート階層に1つずつ置いておけば、すべてのセッションがそれを参照できます。

### 2. `HEARTBEAT.md` が1つで良い理由

今回のアーキテクチャでは、定期的に叩き起こされて「全体を俯瞰して対応漏れがないかチェックする」というハートビートの役割を**メインセッション（司令塔）に一本化**しました。
したがって、Cronタスクがメインセッションを起動した際にインジェクトされる `HEARTBEAT.md` は、ワークスペースのルートに1つあれば完璧に機能します。他のチャンネルのセッションがこのファイルを使うことはありません。

### 3. `AGENTS.md` が1つで良い理由（OpenClawの賢いプロンプト術）

「各チャンネルで振る舞いが違うのに、`AGENTS.md` が1つで大丈夫？」と思われるかもしれませんが、大丈夫です。
OpenClawのデフォルトの `AGENTS.md` テンプレート自体が、**「1つのファイルの中でセッション種別ごとに指示を分岐させる」**という書き方を推奨しているためです 。

例えば、ルートの `AGENTS.md` に以下のように書いておくだけで機能します。

> **【AGENTS.md の記述イメージ】**
> **## 全セッション共通のルール (Every Session)**
>
> - `SOUL.md` と `USER.md` を読み、アシスタントとして振る舞うこと 。
>
> * 最新の状況を把握するため `memory/timeline-YYYY-MM-DD.md` を読むこと。
>
> **## メインセッション（司令塔）限定のルール (If in MAIN SESSION)**
>
> - 個人的な長期記憶である `MEMORY.md` を追加で読むこと 。
>
> * あなたは司令塔です。他チャンネルの状況を監視し、必要なら `sessions_send` ツールを使って介入すること。
>
> **## グループ/チャンネルセッション限定のルール (If in SHARED CONTEXT)**
>
> - セキュリティのため、`MEMORY.md` は絶対に読まないこと 。
>
> * 自分のいるチャンネルの会話にのみ集中すること。

### 結論としてのディレクトリ構造

結果として、あなたのワークスペースは非常にスッキリとした、メンテナンス性の高い構造になります。

```text
~/.openclaw/workspace/
 [cite_start]├── AGENTS.md        (全セッション共通、1つだけ) [cite: 376]
 [cite_start]├── SOUL.md          (人格定義、1つだけ) [cite: 376]
 [cite_start]├── USER.md          (ユーザー情報、1つだけ) [cite: 589]
 [cite_start]├── HEARTBEAT.md     (司令塔用、1つだけ) [cite: 376]
 [cite_start]├── MEMORY.md        (長期記憶、司令塔のみアクセス) [cite: 506, 589]
 └── memory/
      [cite_start]├── YYYY-MM-DD.md           (司令塔の日次メモ) [cite: 589]
      └── timeline-YYYY-MM-DD.md  (全チャンネルの統合タイムライン)

```

このように、**設定ファイルは中央集権（1つ）にしつつ、コンテキストの読み込みルールでエージェントの振る舞いを分ける**のが、OpenClawにおける最も美しく破綻しない設計です。ユーザー様の直感はシステムアーキテクチャのベストプラクティスを完全に捉えています！
